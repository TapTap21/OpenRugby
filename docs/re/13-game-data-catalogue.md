## 2. Binary text formats and parsers

### 2.1 LOCH (`.loc`) - `loch.py`
Chunks `LOCH` (header, offset of `LOCL`), `LOCI` (count, then `count` pairs u16 id, u16 string index) and `LOCL` (count, u32 offsets from the chunk start, UTF-16LE NUL-terminated strings). Six files, 14 or 40 strings each. They hold only platform **save/load dialogue** text (e.g. "Do you want to overwrite previously saved game?", "Unable to save %1.") plus two version strings `2.03.12`/`2.08.04`; English and French variants. They are not the in-game text. `%1` is a positional substitution token.
CLI: `python -m openrugby_tools.loch <file> [-o out.json]` (auto-detects LOCH vs string table).

### 2.2 HBS string table (`.english`, `.french`) - `loch.py`
This is the main game string table, compiled by `hbsstringcompiler` from `stablesku.xml`. Header u32 entry_count (2530 EN, 2531 FR), u32 payload bytes (= file size - 12), u32 max id (2848); then `count` entries of u16 id + NUL-terminated cp1252 string. Ids are sparse (0 to 2848). Verified: every entry parsed, payload size and max id match. Contents: tutorial/drill instructions (with `$HANDOFF`-style button tokens), mission texts, stadium and city names ("Watford, England" id 2848), dialogs. `MISSION` files refer to ids via `title`/`description`/`StringTableID`/`str_table` (`-1` means inline text in the mission file). Dumps for reference: `.omc/research/gamedata/strings_english.json`, `strings_french.json` (gitignored research area).

### 2.3 FntF (`.ffn`) - `fntf.py`
Nine bitmap fonts. Header (all LE): magic, u32 file size, u16 414 (unknown constant), u16 glyph count (95 to 194), u32 0, then offsets (glyph table start 0x80, table end, a secondary block offset), and floats `1/atlas_w`, `1/atlas_h` at 0x40/0x44 (atlas is 256x256 or 256x128 or 128x128). Glyph table: `count` x 12 bytes: u16 code, u8 w, u8 h, u16 x, u16 y (atlas pixels), u8 advance, i8 y_offset (255 = -1), u16 extra (low byte mostly 5, meaning unknown). The atlas is **RGBA8 stored at the end of the file** (file size - w*h*4). Verified by overlaying the glyph rectangles on the decoded atlas: every box lands on its glyph (latin-1 letters, digits, plus in-atlas icons/buttons such as ball icons for codes in the 0x80+ range). Unknown: the 520-byte block between glyph table and extra header words (kerning?), the secondary header offsets, and `extra`. Mod hook: fonts are plain atlas + metrics so replacement fonts only need the same code to rect mapping.
CLI: `python -m openrugby_tools.fntf <file> -o <dir>` writes `<stem>.png` and `<stem>.json`.

### 2.5 hdr_eng / dat_eng pairing
Documented in `docs/re/03-audio.md`; unchanged. Added here: the `hbstool` XML files (3.1) are the **speaker-name id tables** for commentary: `<gfcommentary id="1616" name="Wakely">` corresponds to `dat_eng.big/1616_Wakely.dat`. Checked: of 2601 `NNNN_<Surname>` clips, 2206 match an id+name pair exactly in the 51 `hbstool` files (2355 distinct ids); the 395 misses are name spelling differences or ids absent from the XMLs (not investigated). So `NNNN_Surname` clips are player-name speech, id = commentary-name id. (`observed` for the match, `inferred` that the ids are the database player ids.)
`data.gob` `<sounds count="1284">` (hashes 577964d6, eb487717): `snd id -> byte offset` table with 1284 entries = number of `ref_eng.big` members (referee clips); it is an offset index into a concatenated audio blob for the referee/tutorial speech (inferred).

### 3.2 MISSION (`.mis`)
Root attributes: `name`, `date`, `type`, `league`, `halflength` (minutes), `stadiumid`, `hometeamid`/`awayteamid`, `diff`, `matchtype`/`matchsubtype`, `control`, or story variants with `location`, `easy/medium/hard`, `pro`, `elite`. Children: `TEAM_LIST` of `TEAM_SELECTOR id opponent_id`; `GAME/ENVIRONMENT/WEATHER` (`sky pitch temp time precipitation`, `WIND power x y z`); `GAME/STATE`: `MODE name offensiveteam` (observed `KICK OFF` 37, `FORMATION` 9, `LINE OUT` 8, `PEN K` 3, `FREE` 2), `TIME seconds` (match clock in seconds; e.g. 4700), `SCORE` list of `EVENT type SS_TRY|SS_CONVERSION|SS_PENALTY|SS_DROPGOAL, team, player (shirt number or "kicker"), time`, `NIS`; `OBJECTIVES` of `OBJECTIVE name type mustpass` with `PARAMETER name value`; `SCREENS` with `PREGAME`/`POSTGAME` text (tokens `$USER_TEAM$`, `$USER_LAST$`); `UNLOCKABLES`. Objective types: `ScoreWithPlayerRange` 30, `ScoreType` 18, `WinMatch` 15, `GamePlay` 15, `SellPlayer` 2, `BuyPlayer` 2. Parameter keys seen include `try`, `dropgoal`, `any_score`, `longpass`, `handoff`, `sidestep`, `offload`, `dummypass`, `up_and_under`, `interception`, `dive_on_ball`, `rucks`, `scrums`, `lineouts`, `setplay`, `num_required`, `in80minutes`, `time_limit`. Mod hook: missions are fully data driven and can be reproduced from this schema. Matchtype/matchsubtype enums: not decoded (unknown).

## 6. Commentary event table (pbp.evt)
`Audio/pbp.evt` (78375 bytes) is the "SED" (sound event) database for commentary; the exe also names `pbp_fre.evt`, `hdr_fre.big`, `dat_fre.big` and log strings with priority classes (PRIORITY_1/2/3, `_DISCARD`, `_INVALIDATE`, `PRIORITY_YAK`), flags `SaidLastComment`, `Critical Section`, `Interrupt`. Parser `pbp.py` explains 100 % of bytes structurally; rule semantics are mostly unknown (loader code was not inspected).

Layout (LE, observed): u32 `0x073c1203` magic; u32 end-of-records offset (0xb9b8, also name-table offset); u16 event_count = 612 at 0x10; u16 table of record offsets (value*4) at 0x18; variable-length records 0x4e0 to 0xb9b8; name table (612 x 32 bytes: u32 string-pool offset, u16 tag 7777, u16 hash unknown) at 0xb9b8; string pool at 0x10638 with names such as `C_KNOCK_ON_DROP_CATCH`, `M_FIGHT_BIG` (prefixes M_ 441, C_ 168, DGS_ 2, CHITCHAT 1; M_ = main play-by-play, C_ = colour commentary, inferred).
Record: `u16 id, u16 field_a, u16 field_b, u16 rule_count, u8 flags, u8 percent, u8 x, u8 y, u16 rule_offsets[]`, optional preamble, then rules `u8 kind, u8 percent, u16 n, words`. field_a is 200 (590 events), 300 or 400; field_b about 500 (priority/cooldown guesses, unproven); percent always 100; 1379 rules total, 497 records with one rule, max 51 (C_DROPGOAL). Simple rules `[0,3,X,0]` with X equal to the event id in 363 cases; conditional rules `[1,4,mask,X,0]` (bitmask condition, inferred).
Event to clip: stripping `M_`/`C_` gives a `dat_eng.big` member name for 310 of 612 events (e.g. `M_FIGHT_BIG` to `FIGHT_BIG`, a container of several takes). The other 302 have no same-named clip. No explicit cooldown/probability/priority field has been identified: unknown. Details: `.omc/research/gamedata/pbp-notes.md`.
CLI: `python -m openrugby_tools.pbp <file> [-o out.json]`.
